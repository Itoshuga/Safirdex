# Internationalisation

Safirdex utilise `next-intl` avec des routes toujours préfixées par la langue (`/fr`, `/en`). La configuration de référence se trouve dans `src/lib/i18n/locales.ts` et la configuration de routage dans `src/i18n/routing.ts`.

Les textes d’interface sont organisés par domaine dans `messages/<locale>/`. Les traductions des données métier (cartes, saisons, éditions, raretés, types et lexique) restent dans Firestore sous leur champ `translations`.

## Ajouter une langue

Pour ajouter l’espagnol :

1. Ajouter `"es"` à `SUPPORTED_LOCALES` dans `src/lib/i18n/locales.ts`.
2. Ajouter ses informations dans `LOCALE_CONFIG` (`code`, `label`, `nativeName`, `shortLabel`, `dateLocale`).
3. Créer `messages/es/` en copiant exactement la structure de `messages/fr/`.
4. Traduire toutes les valeurs sans modifier les clés.
5. Exécuter `npm run i18n:check`, `npm run typecheck` et `npm run build`.

`fr` est la langue de référence. Le script de vérification signale les fichiers et clés manquants ou supplémentaires dans les autres langues.

## Conventions

- Utiliser `getTranslations` dans les composants serveur et les metadata.
- Utiliser `useTranslations` dans les composants client.
- Importer `Link`, `redirect`, `useRouter` et `usePathname` depuis `src/i18n/navigation.ts` pour toute navigation interne.
- Utiliser les messages ICU pour les pluriels et les interpolations.
- Utiliser `getTranslation` dans `src/lib/i18n/get-localized-value.ts` pour les contenus Firestore. Le fallback est : locale courante, français, anglais, première traduction disponible.
- Ne jamais traduire les IDs, slugs, statuts ou valeurs techniques stockés.
